01 · OVERVIEW

Structured inputs and traceable candidates

Purpose

Failure Mode and Effects Analysis considers possible failures, their effects and how they could be detected. SafeStop uses an LLM to prepare candidates that an engineer can examine and correct.

Inputs

YAML files describe the architecture, assumptions and draft safety requirements. A controlled prompt defines the task, evidence references and required response format.

Example system

ESTOP-01 / CH-A / CH-BEmergency-stop demand and two input channels
CTRL-01Channel monitoring, output control and reset logic
Q1 / Q2Safety outputs and associated wiring
K1 / K2Series contactors; either opening is assumed to remove drive power
EDM-01Contactor feedback monitoring
RESET-01 / SUP-01Manual reset and 24 V control supply

02 · WORKFLOW

From system evidence to review reports

1

Read the evidence

Load and check the system, assumptions and requirements files.

2

Request candidates

Send the evidence, prompt and required JSON format to Gemini through its API.

3

Check the response

Validate required fields, evidence IDs and defined consistency rules.

4

Save the record

Store the accepted candidate JSON and metadata describing the run.

5

Build reports

Create Markdown and Excel outputs as downloadable GitHub Actions artifacts.

6

Review the analysis

Check the reasoning, record corrections and enter engineering ratings.

Execution: GitHub Actions runs generation and report creation after a manual start. A separate workflow builds reports from saved candidates without an API call.

04 · ENGINEERING REVIEW

Review beyond the software checks

Architecture and effects

Check each causal chain against the supplied architecture, including the assumed independence and series arrangement of the contactors.

Distinct mechanisms

Check for bundled or overlapping failures. Text-based duplicate checks cannot identify every semantic duplicate.

Evidence and uncertainty

Review whether references support the statements and resolve assumptions or missing information before accepting a candidate.

Ratings and decisions

An engineer enters Severity, Occurrence and Detectability. RPN is calculated after those entries; final decisions remain with the reviewer.

Project limits

The system and rating criteria are illustrative. The outputs do not verify a real machine or establish SIL/PL, standards compliance or certification.
