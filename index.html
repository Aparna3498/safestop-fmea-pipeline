01 · PROJECT OVERVIEW

Controlled evidence in, reviewable FMEA candidates out.

The problem

Early FMEA work can take significant time because system evidence must be converted into a consistent set of candidate failure modes. General-purpose AI may help, but it can also create duplicates, unsupported assumptions or incorrect causal chains.

The objective

Build a reproducible workflow that converts controlled safety evidence into structured, reviewable FMEA candidates, validates the output, generates artifacts and compares the result against a predefined human reference FMEA.

System boundary

ESTOP-01 / CH-A / CH-BTwo-channel emergency-stop demand input and field wiring
CTRL-01Channel monitoring, diagnostic logic, output control and reset logic
Q1 / Q2Independent safety outputs and associated field wiring
K1 / K2Two series contactors; either one opening is assumed to remove drive power
EDM-01Contactor auxiliary-feedback loop used before reset
RESET-01 / SUP-01Deliberate manual reset and 24 V control supply

02 · PIPELINE

AI proposes. Automation validates. Human review decides.

1

Prepare evidence

Store system definition and assumptions as controlled YAML data.

2

Generate candidates

Use a fixed prompt with defined boundaries, fields, uncertainty rules and prohibited claims.

3

Validate structure

GitHub Actions checks required JSON fields and allowed classifications.

4

Build artifacts

Generate JSON, Markdown and Excel outputs for review and traceability.

5

Perform human review

Review causal chains, add illustrative S/O/D values and record corrections.

6

Calculate trial metrics

Measure reference matches, valid additions, duplicates and error categories.

Automation boundary: Candidate generation is manual. Validation, calculations and artifact generation are automated with GitHub Actions, preserving human control and avoiding paid API dependency.

04 · ENGINEERING FINDINGS

The useful part was not “AI made rows.” It was making quality measurable.

Architecture matters

The two-series-contactor rule prevented the analysis from incorrectly claiming that one welded contactor always leaves drive power present.

Granularity was the main weakness

Some candidates combined distinct physical mechanisms, reducing strict one-row/one-reference coverage.

Uncertainty is visible

Low-confidence candidates expose where schematics, configuration evidence or component data would be required before accepting the analysis.

Human review stays mandatory

The comparison remains draft AI-assisted mapping for assessor confirmation, not independent verification or final FMEA approval.

Reference gaps in TRIAL-01

  • FM-009: Separate K2 welded-closed mechanism was not generated.
  • FM-014: Reset logic accepting a held level was not surfaced as the exact mechanism.
  • FM-016: OUT-Q1 field-wire short to 24 V was bundled with another output mechanism.
